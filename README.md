# Kaleidoscope

A symmetry drawing toy. You scribble, the scribble blooms into a mandala. Drawing
is free and needs no account. Sign in and you can save pieces to a hosted gallery,
get a permalink, and remix other people's work.

**Live:** https://kaleidoscope.ponderance.dev, plus a native iOS app and a home
screen widget that shows a random piece from the gallery.

## The drawing

A drawing is a list of vector strokes, not pixels. Points are normalized to the
shorter half-axis with the origin at the center, so a drawing isn't tied to the
screen it was made on.

That one choice pays for undo/redo, export at any resolution, real SVG, animated
replay, remix, and saves measured in kilobytes. The PNG you download is one render
of the drawing, not the drawing itself. History keeps 250 snapshots and a piece is
capped at 256KB of vector JSON, which is more scribbling than it sounds like.

Symmetry is rosette group math (`src/client/engine/symmetry.ts`). C_n gives n
rotations, D_n gives n rotations plus a reflected copy, so 2n images. It's well
defined for odd and even n alike, which the old toy's `i % 2` version was not.
Segments run 3 to 24 and default to 12.

## Two clients, one engine, byte for byte

The web engine (`src/client/engine`) is plain TypeScript with no framework
anywhere near it: symmetry math, the stroke model, serialization, the live
canvas renderer, and every exporter. The live renderer and the SVG/PNG/replay
exporters all read the same symmetry code, so they can't drift apart.

iOS doesn't call that engine. It reimplements it in Swift (`ios/KaleidoEngine`,
pure Foundation, runs headless under `swift test`). Two implementations of the
same math is an excellent way to end up with two different answers, so the Swift
serializer is held to producing byte-identical output to the web one.
`ios/tools/gen-engine-fixtures.ts` runs the actual web serializer to emit
`golden.json`, and `SerializeGoldenTests` checks Swift against it. Regenerate
with `npx vite-node ios/tools/gen-engine-fixtures.ts`. Don't hand-edit the
fixtures, or the test is checking Swift against your typing.

**Web:** Preact and `@preact/signals`, state in `src/client/state.ts`, client-side
routing, keyboard shortcuts throughout. It's a PWA, so drawing works offline.

**iOS:** SwiftUI, iOS 17+, universal, three tabs (Draw, Gallery, You). The canvas
renders through Core Graphics. The project is generated by XcodeGen and the
`.xcodeproj` is gitignored, so edit `ios/project.yml` and regenerate instead of
clicking around in Xcode. Build numbers come from `git rev-list --count HEAD` at
build time rather than from someone remembering to bump them.

**Widget:** `RandomWidget` shows a random public mandala in small, medium, or
large, with an interactive reshuffle. Tapping it opens
`kaleidoscopewidget://p/<id>` in the app. It pulls a batch from
`/api/gallery/random` and pre-bakes a rotating timeline, which is why that
endpoint is `no-store`.

## Backend

One Cloudflare Worker does all of it. Workers Static Assets serves the SPA from
the edge and a Hono API lives in the same Worker. `run_worker_first` routes
`/api/*`, `/og/*`, `/p/*`, and `/sitemap.xml` to the Worker. Everything else comes
off the edge cache.

### Auth

Google OAuth 2.0 (authorization code + PKCE/S256, id_token verified against
Google's JWKS) and Sign in with Apple (identity token verified against Apple's
JWKS). Both JWKS are cached in KV.

Sessions are opaque and server-side in KV. The cookie carries a random 32-byte id
and never a JWT, so revoking one is instant. Web clients get a `__Host-` cookie
plus CSRF double-submit and an Origin allowlist. Native clients send that same
session id as a Bearer token and skip the CSRF check deliberately: CSRF exists
because browsers attach cookies to requests you didn't make, and there's no
ambient credential to forge here.

### Storage

D1 holds users and artwork metadata. R2 holds `vec/{id}.json.gz` as the source of
truth, plus webp renders (image, thumb, og) and cached avatars. The bucket is never
public. The Worker proxies it and checks visibility first. KV holds sessions,
transient OAuth state, rate-limit counters, and the JWKS caches.

One wrinkle worth knowing before you touch `migrations/`: `0002` drops the child
table before the parent, because `DROP TABLE users` fires an implicit cascading
delete that `PRAGMA defer_foreign_keys` won't save you from. Deferral delays the
foreign-key *checks*, not the cascade *actions*.

### AI

Every save fires a Workers AI vision call in the background to write alt text.
`POST /api/artworks/suggest-names` runs a caption model and then an instruct model
to propose titles, and returns an empty list rather than an error if either one
misbehaves. There's an admin route to backfill alt text over old pieces in bounded
batches.

### Abuse defense

Turnstile on save (cookie sessions only) and KV rate limits: 60 saves/hour,
300/day, 120 likes/hour, 30 name suggestions/hour. There's no monthly cap. The
`flagged` and `role` columns exist for curation if it ever needs it.

## Develop

```bash
npm install
npm run dev            # vite + worker in workerd (http://localhost:5173)
npm run typecheck      # tsc -b (project refs: client / worker / node)
npm run lint
npm test               # vitest: unit + worker tests
npm run test:e2e       # playwright (starts the dev server itself)
npm run build
npm run db:migrate     # d1 migrations, --remote
npm run db:migrate:local
```

**Deploying.** The supported path is a push to `prod`, which runs the whole gate
in CI and then migrates and deploys. `npm run deploy` exists for the rare
hand-deploy and now runs that same gate itself — typecheck, lint, tests, build,
**migrations**, then `wrangler deploy`.

It used to be `vite build && wrangler deploy`: no gates, no migrations, and it
shipped the working tree including uncommitted changes. Deploying 1.2's worker
that way against an unmigrated D1 answers `no such column` to every save,
`/api/me` and billing call. `deploy:unsafe` is still there for when you
genuinely mean it — the name is the point.

Local secrets live in `.dev.vars` (gitignored). For local OAuth it points
`PUBLIC_BASE_URL` and `GOOGLE_REDIRECT_URI` at `localhost:5173` and sets
`ALLOW_TEST_LOGIN=true`, which enables `POST /api/auth/test-login`, a session
bypass for dev and tests. Never set that in production.

The dev server binds `host: true` and allows `.ts.net`, so you can open it on your
phone over Tailscale.

⚠️ **Over Tailscale you must reach it as `https://`, not `http://`.** The
drawing's content hash goes through `crypto.subtle`, which the browser exposes
only in a **secure context** — `localhost` counts, `http://<host>.ts.net` does
not, and `window.crypto.subtle` is then simply `undefined`. Nothing errors
visibly: `contentHash` throws, the save dialog catches it and skips the duplicate
pre-flight (so every `Save*` state that depends on the hash is unreachable), and
the artwork page can no longer tell a remix from its parent. Service workers have
the same rule, so the whole PWA — offline shell and the "Update available"
prompt — is inert there too. Testing any of that over `http` on a tailnet tests
the degraded path, silently.

Give Vite a certificate for the tailnet hostname and turn on `server.https` in
`vite.config.ts`:

```bash
tailscale cert <host>.ts.net       # writes <host>.ts.net.crt / .key
```

```ts
// vite.config.ts — server: { ... }
https: { key: readFileSync("<host>.ts.net.key"), cert: readFileSync("<host>.ts.net.crt") },
```

`localhost` needs none of this and is the right target for everything that is not
specifically about a phone or an iPad.

## Tests

Vitest covers the symmetry group math (`forEachImage` for C_n and D_n), stroke
normalize/serialize round-trips, SVG export, validation caps, and the Worker
routes. Playwright drives the real flows: draw and download with no login, then
mock sign-in, save, permalink with OG tags, gallery, remix, delete. Swift side,
`swift test` runs the engine tests including the golden-file check against the web
serializer.

CI (`.github/workflows/deploy.yml`) runs on pushes to `prod`: typecheck, test,
build, D1 migrations, deploy. It doesn't run lint or e2e, and there's no iOS CI.
App Store screenshots in `ios/app-store-screenshots/` are produced by hand.

## Capacity

The SPA is static and served from Cloudflare's edge cache, so concurrency there is
effectively unbounded. Drawing is entirely client-side and costs nothing while
someone scribbles. The Worker runs on sign-in, saves, gallery reads, and the image
proxies, and those are edge-cached after the first hit.

A save is a Turnstile verify, a couple of KV and D1 writes, a few small R2 puts,
and one Workers AI vision call for alt text. The AI neurons are the part most
likely to cost money at volume, not the storage. Storage stays small because the
source of truth is vector JSON rather than big PNGs.

## Operations

Turnstile runs on a real widget for `kaleidoscope.ponderance.dev`.
`TURNSTILE_SITE_KEY` is a var in `wrangler.jsonc` and `TURNSTILE_SECRET_KEY` is a
Wrangler secret.

Grant yourself admin after signing in once:

```bash
wrangler d1 execute kaleidoscope --remote \
  --command "UPDATE users SET role='admin' WHERE email='you@example.com'"
```

Web Analytics is cookieless and turns on through the Cloudflare dashboard. The CSP
already allows the beacon origins.

### Releasing the iOS app

Set the App Store **Support URL** to `https://ponderance.dev/support/kaleidoscope/`
— with the trailing slash, since the bare path 307s. It currently points at the
`ponderance.dev` hub, which makes a user hunting for help find every app but this
one.

Fix it **while the version is still editable.** Apple refuses the change on a
`READY_FOR_SALE` version: `PATCH /v1/appStoreVersionLocalizations/{id}` answers
`409 STATE_ERROR — "Attribute 'supportUrl' cannot be edited at this time"`
(verified 2026-07-31). So this is release-time work, not a thing that can be
cleaned up afterwards.

Keep `package.json` `version` equal to the iOS `MARKETING_VERSION`, as the plain
string Apple shows — `1.1`, not `1.1.0`. Orrery compares the two sides as raw
strings, and App Store Connect reports the version exactly as entered.
